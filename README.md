# AnyDesk Auto Confirm

Отдельное приложение на Kotlin для **Xiaomi / Android 7.1.2 (API 25) / MIUI 10**. Автоматически вызывает Accessibility `ACTION_CLICK` для кнопки «НАЧАТЬ» в распознанном запросе трансляции AnyDesk. Не зависит от Boiler Watch, MacroDroid, Google Play Services, регистрации, подписки, root или ADB во время эксплуатации.

**Статус 1.0.1:** Debug APK собран настоящими Android SDK-инструментами; прошли 52 тестовых запуска JUnit/Robolectric, включая Android API 25 и 35. Все ссылки APK на Android API разрешаются на API 25. На физическом Xiaomi установка и работа ещё не подтверждены. Причина сообщённого зависания установки пока не установлена. Успешный вызов `ACTION_CLICK` не доказывает установление соединения. Работа с выключенным экраном и после перезагрузки требует приёмки на телефоне до потери физического доступа.

## Первичная настройка

1. Перенесите APK на Xiaomi, разрешите установку из неизвестных источников и установите его.
2. Откройте **AnyDesk Auto Confirm**. Автоматизация и установка галочки изначально выключены.
3. Нажмите **«Открыть специальные возможности»**, найдите **AnyDesk Auto Confirm**, включите службу вручную и подтвердите системное предупреждение.
4. Вернитесь в приложение, включите **«Автоматически подтверждать AnyDesk»** и нажмите **«Проверить состояние»**. Нужен статус **«Активна»**. AnyDesk `com.anydesk.anydeskandroid` должен быть установлен и включён.
5. При желании включите установку галочки «Больше не показывать». Это не гарантия отмены будущих запросов.
6. Разрешите автозапуск и работу батареи без ограничений в MIUI для этого приложения, AnyDesk и AD1. По возможности закрепите их в недавних.
7. Выполните весь [чек-лист](docs/XIAOMI-CHECKLIST.md), включая выключенный экран, ожидание и перезагрузку, прежде чем оставлять телефон на месяцы.

После настройки MainActivity не нужна для повторных подключений. Для отключения достаточно выключить основной переключатель; для полного отзыва доступа выключите службу в специальных возможностях.

## Архитектура и структура

```text
app/src/main/
  AndroidManifest.xml
  java/ru/denis/anydeskconfirm/
    MainActivity.kt
    accessibility/
      AnyDeskAccessibilityService.kt
      DialogDetector.kt
      DialogConfirmer.kt
      AttemptLimiter.kt
      WindowCapture.kt
      ServiceState.kt
    settings/SettingsRepository.kt
    diagnostics/DiagnosticLogger.kt
  res/layout/activity_main.xml
  res/xml/accessibility_service.xml
  res/values/{strings,styles}.xml
  res/drawable/ic_app.xml
app/src/test/                 # 52 тестовых запуска JUnit/Robolectric
app/src/androidTest/          # 2 инструментальных теста конфигурации и настроек
gradle/wrapper/               # официальный Gradle Wrapper с SHA-256 дистрибутива
scripts/                     # обычная сборка и SDK fallback, проверки APK
docs/                        # инструкции, приёмка, отчёт
artifacts/                   # APK, контрольная сумма, протоколы
version.properties           # версия для Gradle и SDK-сборки
```

Службой управляет Android через штатный механизм Accessibility. Обрабатываются `TYPE_WINDOW_STATE_CHANGED`, `TYPE_WINDOW_CONTENT_CHANGED` и `TYPE_WINDOWS_CHANGED`. В конфигурации ограничены пакеты событий: System UI и AnyDesk. Для событий смены окон с пустым пакетом всё равно проверяется пакет активного корня, содержимое чужих приложений не обходится.

События объединяются в одну отложенную проверку через 120 мс без сдвига срока от новых событий. Читается только активный корень `com.android.systemui`, максимум 256 узлов и 32 уровня. Снимок существует только во время обработки, все полученные узлы освобождаются; в отложенные задачи узлы не передаются.

`DialogDetector` требует одновременно установленный включённый пакет `com.anydesk.anydeskandroid`, пакет System UI у дерева и его элементов, один действительный неотрицательный идентификатор окна, точный поддерживаемый текст запроса с именем AnyDesk и единственную видимую кнопку класса `android.widget.Button` с ID `android:id/button1` и ожидаемым текстом. Поддержаны регистр, переносы, обычные и неразрывные пробелы, русский и английский шаблоны. Слово «НАЧАТЬ» само по себе ничего не разрешает. Неизвестная локализация, неоднозначное или неполное дерево безопасно отклоняются.

Поддерживаемые сообщения после нормализации:

- «Приложение AnyDesk получит доступ к изображению на экране устройства.»
- «Приложение AnyDesk получит доступ ко всему, что отображается на экране.»
- “AnyDesk will start capturing everything that's displayed on your screen.”

Кнопки: «НАЧАТЬ», “START NOW”, “START”. При других текстах требуется осознанно добавить проверенный полный шаблон в детектор и тесты, а не ослаблять проверку до отдельных слов.

`AttemptLimiter` разрешает до трёх попыток в пределах восьми секунд на ID окна, с интервалом не менее 700 мс между попытками. Принятый `ACTION_CLICK` блокирует следующие нажатия для этого окна независимо от повторных событий. В памяти остаются последние 128 распознанных ID: память не растёт со временем. После уничтожения процесса эта защита начинается заново; настройки и диагностика сохраняются. Новое окно проверяется заново, отсутствующий корень и неполное дерево не считаются новым запросом. Если окно сменилось перед повтором, старые узлы не используются.

Опциональная галочка проверяется по `com.android.systemui:id/remember`, классу CheckBox, доступности и текущему состоянию. Уже установленная галочка не снимается. После принятого нажатия на галочку дерево заново читается и полностью проверяется через 180 мс. Отсутствие или ошибка галочки не препятствует обычному подтверждению. Перед непосредственным нажатием целевой узел обновляется через `refresh()`, повторно проверяются пакет, окно, ID, текст и доступность.

SharedPreferences хранит два переключателя и фиксированные поля диагностики: обнаружение, попытку, результат, счётчик принятых команд, последнюю ошибку и событие жизненного цикла. Нет постоянного журнала, дампов экрана, паролей или сообщений исключений с данными окна. Запись через `apply()` не блокирует основной поток синхронной записью на диск.

Нет foreground-службы, boot receiver, периодического опроса, wakelock, координатных жестов, HOME/BACK, скрытых API или автоматического включения Accessibility. Единственная экспортируемая служба защищена системным `BIND_ACCESSIBILITY_SERVICE`; интерфейса произвольного выполнения нажатий нет. Manifest не запрашивает никаких `uses-permission`, включая INTERNET.

## Сборка обычным способом

Проверенная совместимая связка: **JDK 17, Gradle 8.11.1, AGP 8.9.2, Kotlin 2.1.20, compileSdk/targetSdk 35, Build Tools 35.0.0, minSdk 25**. Версии зафиксированы; динамических и экспериментальных зависимостей нет. Единственная runtime-зависимость — стандартная библиотека Kotlin. AndroidX/JUnit/Robolectric используются только в тестах.

Установите JDK 17 и Android SDK. Для SDK достаточно `platforms;android-35` и `build-tools;35.0.0`; для инструментальных тестов также platform-tools и устройство/эмулятор. Примите лицензии SDK локально. Настройте `JAVA_HOME` и `ANDROID_HOME`, затем:

```sh
./scripts/build.sh
```

Либо отдельно:

```sh
./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Стандартный APK появляется в `app/build/outputs/apk/debug/app-debug.apk`. Скрипт также копирует его в `artifacts/` и проверяет конфигурацию и подпись. При первом запуске нужны интернет для Gradle/зависимостей и около 2 ГБ памяти; после заполнения кеша возможен `--offline`. Интернет нужен компьютеру сборки, приложение сети не использует.

Для инструментальных тестов на подключённом тестовом устройстве/API 25:

```sh
./gradlew connectedDebugAndroidTest
```

Здесь инструментальные тесты **не запускались**: sandbox запрещает локальные сокеты Gradle и ADB. Сборка Gradle в этой среде остановилась до конфигурации проекта. Поставляемый APK действительно собран другим воспроизводимым путём: `aapt2 → javac/Kotlin → D8 из AGP → zipalign → apksigner`. Инструменты и зависимости взяты из существующих локальных установок и скопированного кеша; код и настройки Boiler Watch не менялись. Подробности в [отчёте](docs/VALIDATION.md).

Для такого же fallback при уже имеющихся SDK и кеше:

```sh
python3 scripts/build-with-sdk.py --tests
python3 scripts/lint-with-sdk.py
python3 scripts/verify-project.py
python3 scripts/package-source.py
```

Fallback ничего не скачивает. Требует заполненный `GRADLE_USER_HOME` (либо `.gradle-user-home/`) и для Robolectric локальные SDK JAR в `.tools/robolectric-m2`. Эти большие локальные инструменты не входят в исходную поставку и не нужны установленному приложению. Для воспроизведения в обычном окружении предпочтителен Wrapper. Standalone Lint нужен доступ на запись в используемый SDK для кеша API либо отдельная его копия.

APK подписан отдельным локальным отладочным ключом `.tools/debug.keystore`. Сохраните его для обновлений установленного APK: Gradle использует его, если файл существует. При другом ключе Android не разрешит обновление поверх установленной версии; удаление приложения сбросит настройки и потребует повторного включения Accessibility. Ключ не включается в архив исходников. Байт-в-байт идентичность разных APK не обещается: подпись и ZIP-времена зависят от окружения.

В 1.0.1 схемы подписи v1/v2/v3 включены явно, v1 дополнительно проверяется отдельно. Исходная версия 1.0.0 также имела корректную v1-подпись: её отсутствие не было причиной зависания. На телефоне пока не подтверждена установка ни одной версии.

## Ограничения безопасности и доступности

Accessibility видит текст и структуру диалога, но не предоставляет проверенный UID инициатора MediaProjection на этом Android. Наличие официального пакета и точный шаблон сильно ограничивают автоматизацию, **но не являются криптографическим доказательством заявителя**: другое установленное приложение с названием AnyDesk способно имитировать имя в системном запросе. Не устанавливайте недоверенные приложения на этот телефон. Служба не требует недавнего события из AnyDesk: это сломало бы работу после восстановления процесса и при выключенном экране.

MIUI может убить процесс или отключить службу. Android обычно сам восстанавливает разрешённую AccessibilityService, однако без привилегий нельзя гарантировать восстановление после вмешательства MIUI, принудительной остановки или перезагрузки. Если после загрузки требуется первый ввод PIN/пароля, служба может быть недоступна до первого разблокирования. Приложение не снимает блокировку и не будит устройство; при скрытом дереве окна оно ничего не нажимает. Если AnyDesk не показывает запрос при выключенном экране, Accessibility тоже не сможет его подтвердить.

Это помощник для одного системного диалога, не замена настройке неконтролируемого доступа AnyDesk/AD1 и не гарантия многомесячной доступности. Детали диагностики и сценарии восстановления — в [инструкции MIUI](docs/INSTALL-MIUI.md).

Технические основания: [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [флаги получения ID и окон](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo), [совместимость AGP 8.9](https://developer.android.com/build/releases/agp-8-9-0-release-notes). Эти документы описывают платформу и инструменты, но не подтверждают поведение конкретной прошивки MIUI.
