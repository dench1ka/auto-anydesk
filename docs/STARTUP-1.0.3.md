# Подготовка экрана после загрузки — 1.0.3

Цель: устранить необходимость вручную свайпать после перезагрузки выделенного Xiaomi Android 7.1.2 / API 25 / MIUI 10. Владелец сообщил, что предыдущая версия нажимает «НАЧАТЬ» после ручного свайпа, но за блокировкой после загрузки не срабатывает. Новая версия собрана и проверена автоматически; **на физическом Xiaomi этот режим ещё не проверен**.

## Причина и пределы решения

Прежняя служба только распознавала доступное дерево системного окна и нажимала кнопку. Она не снимала блокировку. По наблюдению владельца блокировка мешает сценарию; без журналов телефона нельзя точно разделить скрытое дерево, задержку запуска Accessibility/AnyDesk и недоступность данных пользователя до первого разблокирования.

Для API 25 добавлено явное согласие владельца: настройка **«Режим без присмотра после загрузки»**, изначально выключенная. Она работает только вместе с основной автоматизацией и вручную разрешённой службой Accessibility при установленном включённом AnyDesk. PIN, пароль, графический ключ и PIN SIM отклоняются; пароль расшифровки при включении не вводится.

Используется публичный `KeyguardLock.disableKeyguard()` с обычным разрешением `DISABLE_KEYGUARD`. Это устаревший API, выбранный намеренно для целевого Android 7.1; защищённую блокировку он не отменяет. При выключении режима/автоматизации или отключении службы вызывается `reenableKeyguard()`. [Документация Android](https://developer.android.com/reference/android/app/KeyguardManager.KeyguardLock).

Приложение не меняет системную настройку способа блокировки: оно временно просит не применять свайп, пока режим и процесс службы работают. Смерть процесса или политика MIUI могут прекратить действие. Если владелец приемлет отсутствие экрана блокировки, его можно отдельно отключить вручную в штатных настройках телефона.

## Запуск и пробуждение

- `StartupSettings` дублирует два флага согласия и одно фиксированное диагностическое сообщение в device-protected storage. Пароли, экран, основная диагностика и остальные предпочтения туда не переносятся.
- Приватный `BootReceiver` принимает только `LOCKED_BOOT_COMPLETED` и `BOOT_COMPLETED`. Он читает только раннее хранилище, проверяет условия и однократно запрашивает подготовку. При выключенном режиме ничего не открывает.
- При подключении Accessibility подготовка повторяется. Затем пробуждение допускается только по `TYPE_WINDOW_STATE_CHANGED` AnyDesk либо по полному известному сообщению его трансляции в System UI. Всплески `TYPE_WINDOW_CONTENT_CHANGED` экран не будят.
- `WakeActivity` приватная, видимая, исключена из недавних. Пустая taskAffinity позволяет открыть её отдельно от главного экрана помощника. Использует `TURN_SCREEN_ON`, `SHOW_WHEN_LOCKED`, `DISMISS_KEYGUARD`, завершает работу через 800 мс либо при потере переднего плана. Интервал между запросами окон — не менее пяти секунд в процессе. Когда экран уже включён, не заблокирован и данные доступны, окно не открывается.
- После закрытия экран может погаснуть по системному таймауту. `KEEP_SCREEN_ON`, power wakelock, принудительное усыпление, таймер опроса и постоянная foreground-служба не используются.

Оконные флаги доступны на API 25; снятие через `DISMISS_KEYGUARD` ограничено незащищённым экраном. [WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams).

BootReceiver и WakeActivity помечены `directBootAware`. Сама AccessibilityService остаётся обычной: она использует основное хранилище, доступное после разблокирования пользователя. Ранняя подготовка пытается устранить необходимость свайпа до её запуска, но не объявляет credential-protected данные доступными искусственно. [Direct Boot на Android](https://developer.android.com/privacy-and-security/direct-boot).

## Безопасность и конфигурация

Два запрашиваемых разрешения — `RECEIVE_BOOT_COMPLETED` и `DISABLE_KEYGUARD`, оба обычные. `BIND_ACCESSIBILITY_SERVICE` защищает саму службу. INTERNET, WAKE_LOCK, WRITE_SECURE_SETTINGS, WRITE_SETTINGS, Device Admin отсутствуют. BootReceiver и WakeActivity не экспортируются. Accessibility не включается программно; secure settings только читаются для проверки ручного согласия. Нет ввода кода, координатных жестов, HOME/BACK, скрытых API или удалённого интерфейса нажатий.

Пробуждение не является разрешением нажать кнопку. Перед нажатием остаются проверки точного System UI-диалога AnyDesk, пакетов, окна, кнопки, видимости и доступности. Максимум три попытки для окна, принятый ACTION_CLICK подавляет повторные нажатия. Пароли AnyDesk не хранятся.

## Проверка владельцем перед работой без присмотра

1. Обновить APK, открыть помощник, проверить версию 1.0.3 и активность службы. Включить основную автоматизацию и новый режим.
2. Выполнить [настройку MIUI](INSTALL-MIUI.md#режим-без-присмотра-после-загрузки): автозапуск, батарея без ограничений, фоновые окна при наличии, таймаут экрана. AnyDesk и AD1 должны самостоятельно работать после загрузки.
3. Перезагрузить телефон. После загрузки **не касаться экрана**, не свайпать и не открывать приложения. Дождаться мобильной сети и погасшего экрана.
4. С iPhone подключиться через AnyDesk. Проверить появление изображения и управление через AD1. Отключиться и подключиться повторно; повторить после 24–72 часов ожидания и после восстановления мобильной сети.
5. Если не сработало, сначала зафиксировать провал опыта, затем вручную открыть помощник и записать его статус подготовки и обычную диагностику. Текст «запрошена подготовка» означает команду, а не доказанное снятие блокировки или соединение.

Если MIUI не доставляет boot-событие, запрещает фоновое окно, не запускает AnyDesk либо отключает Accessibility, приложение без привилегий не сможет гарантированно восстановить удалённый доступ. Оно также не умеет включить физически выключенный телефон от зарядки. До успешного опыта без касаний обещать доступ после перезагрузки или месяцы автономности нельзя.
