# Повторная проверка приложения и установки

Версия 1.0.1, versionCode 2. Цель — Android 7.1.2 / API 25 / MIUI 10. Проверка выполнена после сообщений о блокировке Google Play Защитой и бесконечной установке.

**Вывод:** проверка не выявила повреждения APK, неправильной подписи или отсутствующих Android API. Причина зависания установщика на конкретном телефоне пока не установлена. Новая сборка устраняет найденные ошибки службы и интерфейса, но не является подтверждённым исправлением установки на Xiaomi.

## Что исправлено

1. После отключения службы от Android отменяются отложенные проверки, удаляется слушатель настроек и запрещается обработка новых событий до подключения. Это закрывает случай, когда изменение переключателя после `onUnbind()` могло снова запланировать чтение окна.
2. Детектор отклоняет окно с недействительным отрицательным ID. Неполные данные Accessibility больше не рассматриваются как идентифицированное системное окно.
3. Переносы строк диагностики и инструкции MIUI заданы как `\n`, кавычки настройки checkbox — как `\"`. Ранее AAPT мог сворачивать физические переводы строк в пробелы и убирать кавычки, что затрудняло чтение на маленьком экране.
4. Перед созданием DEX очищается только каталог результата D8, чтобы повторная сборка не включала старые дополнительные DEX. Версия вынесена в `version.properties` и используется Gradle, SDK-сборкой, проверками и упаковкой.
5. В конфигурации сборки явно включены v1/v2/v3, отключена отдельная v4/idsig-поставка; добавлены отдельная проверка JAR/v1, проверка ZIP/DEX и сопоставление ссылок на Android API с API 25.

Эти изменения не обходят Play Protect, не скрывают Accessibility и не меняют системные настройки телефона.

Проверка Android API выполняется скриптом `scripts/check-api25.py` по реальным ссылкам из поставляемого DEX, включая наследуемые методы. Опорный JAR — кешированный Android 7.1 / API 25 из Robolectric. Контрольный APK с намеренным вызовом `Context.getMainExecutor()` (API 28) был правильно отклонён этим же скриптом. Проверка ограничена Android framework: она не является запуском ART, установщика или прошивки MIUI. Java/Kotlin-зависимости проверяются компилятором, D8, Lint и тестами отдельно.

Подпись v2 официально поддерживается начиная с Android 7.0. Для широкого охвата поддерживаются также JAR/v1 и v3. [Документация Android](https://source.android.com/docs/security/features/apksigning). Важное уточнение: **исходный APK 1.0.0 уже содержал правильную v1-подпись**. Обычный `apksigner verify` при minSdk 25 показывает выбранную схему v2, поэтому строка `v1: false` в таком выводе не доказывает отсутствие v1. Отдельная проверка исходного APK на API 23 проходит. Называть подпись причиной зависания оснований нет.

Исходный APK в публичном GitHub проверен по Git blob SHA: `c7d0022f5f994194906813c82b832302107b3471`, размер 742001 байт. Он совпадает с локально собранной версией 1.0.0. Это подтверждает файл в репозитории, но не завершённость скачивания на телефон.

## Как установить причину зависания

Нужно определить точный этап: **сканирование Google/MIUI**, системное **«Установка…»** или уже **открытие приложения**. Нужны точный текст либо скриншот и длительность ожидания. По одной фразе «бесконечная установка» выбрать причину нельзя. Код Activity и AccessibilityService не запускается обычным установщиком до завершения установки, поэтому исправления обработчика событий не объясняют такой симптом сами по себе.

1. Убедитесь, что открывается именно `.apk`, а не ZIP с исходниками и не HTML-страница GitHub. Размер APK 1.0.1 — 742001 байт, контрольная сумма приведена выше. Размер старого APK случайно совпадает, поэтому различайте их по имени и SHA-256.
2. Для обычной установки откройте новый APK через файловый менеджер. Если зависание повторяется, зафиксируйте точный экран и текст; повторная установка не считается успешной, пока установщик не завершится.
3. Если Google предлагает проверку неизвестного приложения, сначала дождитесь её результата. Утверждать, что предупреждение о вредоносности — ложное срабатывание, без его текста и разбора нельзя. Play Protect может проверять и блокировать APK вне магазина. [Справка Google](https://support.google.com/android/answer/2812853?hl=ru).
4. **Необязательно, только для диагностики первоначальной установки:** если ADB уже доступен на компьютере и телефон разрешает установку через USB, выполните команды ниже. Они нужны для получения конкретного кода PackageManager, приложению в эксплуатации ADB не требуется.

```sh
adb install --no-streaming -r artifacts/AnyDeskAutoConfirm-1.0.1-debug.apk
adb logcat -d -v time PackageManager:I PackageInstaller:I PackageInstallerSession:I installd:I dex2oat:I '*:S'
```

Не публикуйте полный журнал в открытом репозитории; для разбора достаточно результата `adb install` и относящихся к установке строк. Если MIUI запрещает установку через USB, не нужно получать root или обходить защиту: используйте обычный установщик и точное сообщение с его экрана. Факт отказа USB-установки отдельно от ошибки APK.

Пока эти данные не получены и реальная установка не завершена, **зависание не считается исправленным**, а приложение не считается принятым для работы без физического доступа.
